# 0047 — The shader toolchain

**Status:** Accepted (2026-10-28). Names are placeholders (docs/naming.md).

## Context

ADR 0025 makes shaders Slang: engine shaders, and material surface
functions compiled per variant with the engine's lighting code, at import
or build time, never in shipped games, with the material parameter layout
from Slang reflection. Slag takes per-stage lists of tagged binaries (DXIL,
SPIR-V) and needs particular Slang flags (Slag ADR 0034, 0036). M5 step 1
builds the toolchain; decision O settles where Slang runs and the compiled
file format.

## Options

**Where Slang runs:** Slang's library API in Crucible's own C++, used by the
importers and by a build tool built from the same code; the `slangc`
command line everywhere; or `slangc` at build time now and the library
later for materials.

**Source of truth for structs shared by CPU and GPU:** Slang, with C++ and
C# generated from reflection; or C++, with Slang generated by the binding
generator.

**DXIL:** Slang produces it through Microsoft's DXC (dxcompiler), under the
University of Illinois/NCSA licence.

## Decision

1. **One compile path on Slang's library API,** in the importers
   (`crucible_importers`, editor-only). The build compiles engine shaders
   with `crucible_shaderc`, a small tool linked against the same code.
   In-memory compiles, full reflection, and modules cached across a
   material's variants.
2. **Shared structs are written in Slang** and marked `[GpuShared]`; the
   build generates the C++ and C# structs, padding included, with layout
   checks.
3. **DXC is approved** (owner, 2026-10-28) for build time and the editor,
   never shipped: Slang loads it to produce DXIL. Like Slag, Crucible
   builds DXIL only on Windows.
4. **A compiled shader is a binary file** (ADR 0039) of kind `SHDR`: each
   entry point's DXIL and SPIR-V side by side, and what the runtime needs
   to pass them to Slag.

## Details

- **Pinned** like Slag's CI: Slang 2026.18.2 (Linux and Windows release
  archives) and DXC v1.9.2609, by URL and SHA-256 in
  `cmake/CrucibleDependencies.cmake`.
- **Flags:** Slag's required SPIR-V flags; `-matrix-layout-row-major` (ADR
  0024's row vectors); and `-fvk-use-dx-layout`, so buffers have D3D12's
  layouts on both backends. D3D12's structured buffers are packed, which
  Vulkan accepts with `scalarBlockLayout`: mandatory in Vulkan 1.4, and
  now enabled by Slag (its ADR 0012 and 0034, Slag 1.0.2).
- **One layout per shared struct:** a `[GpuShared]` struct must have the
  same offsets and size as a constant buffer and as a structured buffer
  element, on both targets; the build fails otherwise and names the first
  field that differs, so authors add explicit padding where the rules
  disagree. Generated C++ uses 4-byte-aligned members, so its layout is the
  shader's.

## As built (M5 step 1)

- **Compiler** (`crucible/importers/ShaderCompiler.h`, in `crucible_importers`):
  one Slang global session, kept (it loads the core module once) and used
  by one compile at a time. Each compile is a session with three targets:
  SPIR-V, HLSL (only for D3D12's layouts, which need no DXC), and DXIL where
  asked. Every entry point is linked and compiled per target. Slang's
  options are given as `slangc` arguments, and options after a `-target`
  apply to that target only: `-fvk-use-dx-layout` must follow
  `-target spirv`.
- **Layout check:** Slang's per-rule layout query ignores
  `-fvk-use-dx-layout`, so the compiler declares each `[GpuShared]` struct
  as a `ConstantBuffer<T>` and a `RWStructuredBuffer<T>` in a small module
  of its own and compares the layouts Slang gives those, on both targets.
  An error names the field and both offsets.
- **Shared structs** hold 32-bit scalars (bool as uint), float vectors, and
  float4x4. Arrays and int vectors are refused for now. **Nested structs
  are refused too:** NVIDIA's Vulkan driver 621.01 (RTX 2070 Super,
  2026-10) stores and loads a nested struct's members at the outer
  struct's offset 0 in buffers reached through descriptor heaps; the SPIR-V
  is valid, and D3D12 on the same GPU and RADV are right. The repro (a
  shader writing `output[i].tint.strength`, which lands at byte 12 instead
  of 92) is an open item to report.
- **Matrices:** Slang 2026.18.2 already lays matrices out row-major by
  default; `-matrix-layout-row-major` pins it.
- **`crucible_shaderc`** writes `<name>.shdr` and the mirrors
  `<name>.g.h` (with `static_assert`s on size and offsets, using
  `crucible::Vector2/3/4` and `Matrix4x4`, all 4-byte aligned) and
  `<name>.g.cs` (explicit layout, System.Numerics). CMake's
  `crucible_add_shader` (`cmake/CrucibleShaders.cmake`) runs it; shaders
  import Crucible's library from `shaders/` (`crucible/shared.slang`
  declares `[GpuShared]`).
- **Runtime** (`crucible/Shader.h`, core): `loadShaderFile` and
  `shaderStage`, which gives Slag DXIL first, then SPIR-V.
- **Windows:** Slang's and DXC's DLLs are copied beside the core and beside
  `crucible_shaderc`. The core now exports its binary-file writer, which the
  importers' DLL calls.
- **Tests:** a GPU test fills buffers of `[GpuShared]` structs on every
  backend the build has (D3D12 and Vulkan on Windows, Vulkan on Linux) and
  reads them back through the C++ mirrors, including a packed struct (a
  float then a float3: 16-byte stride, which needs Slag's
  `scalarBlockLayout`) and a row-major matrix; compiler tests for each
  refusal; a C# test of the C# mirrors' offsets, under JIT and NativeAOT.
