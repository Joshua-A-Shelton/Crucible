# Review 8: the 2D path

Sprites, sorting layers, the pixel camera, frame animation, tilemaps and
map mode, and 2D lighting: what a pixel-art game (or 2D over 3D) is built
from. 2D physics is page 7's. Decisions: ADRs 0005, 0104, 0106, 0107,
0108, 0112, 0113, 0123, 0124.

## What it does

2D entities have a `Transform2D` on the XY plane and draw as sprites or
tilemaps, ordered by named sorting layers. A pixel camera draws them at a
low resolution and scales the result up crisply, over or under the 3D.
Sprite sheets are cut and animated in an editor of their own; tilemaps
are painted in map mode (the official Tilemaps plugin); 2D lights light
sprites a virtual pixel at a time.

```
 Transform2D + Sprite / Tilemap ─► Sprites step: sorted by layer, order,
 (sorting layer, order in layer)    and y where the layer y-sorts
                                         │  × 2D light buffer
                                         ▼
                    PixelCamera: drawn at 320x180 (say) ─► scaled up sharply
                    over the 3D, or Behind3D under it (where the 3D drew nothing)
```

## How it works

### Sprites and sorting (ADR 0104)

- **`Sprite`:** a texture, a region of it, a pivot, a tint, flips, a
  sorting layer, and an order in that layer.
- **Named sorting layers** in the project file, drawn in order; within
  one, by order in layer, then (if the layer y-sorts) lower on screen in
  front. A map with floors (a bridge walked over and under) is bands of
  layers per floor.

### The pixel camera (ADR 0106)

- **Draw small, scale up:** sprites draw into a texture at the virtual
  resolution, scaled up over the finished image, so rotated or scaled
  sprites stay as coarse as the art and nothing shimmers. The camera and
  every sprite snap to the pixel grid.
- **`Sharp`** fills the window with the largest scale that fits, blending
  only across pixel edges; **`Exact`** scales by whole numbers with bars.
- **Over or under the 3D:** a sorting layer marked `Behind3D` draws under
  the 3D wherever it drew nothing.

### Frame animation (ADR 0107)

- **The Sprite Sheet Editor** cuts a texture into frames (a grid, or
  rectangles dragged out) and builds clips of frames with durations and
  events, previewed as you edit. Clips are sub-assets of the texture.
- **`SpriteAnimator`** plays a clip on its Sprite, or lets a state machine
  (the same `.crstates` as 3D) choose.

### Tilemaps and map mode (ADR 0108, 0112, 0123, 0124)

- **Tilesets** are assets: a texture cut into tiles, with collision shapes
  per tile (any outlines). **Maps** are assets: cells (position, tile,
  flips) per layer, using one or more tilesets.
- **A map is an entity with a child per layer;** each layer's `Tilemap`
  draws it, and a layer that collides has a static body with the map's
  merged outlines.
- **Map mode** (now the official Tilemaps plugin, ADR 0123): the Palette,
  the map's own view with Stamp, Rectangle, Fill, Eraser, and Select, and
  the Layers panel; the map file follows its entity through rename,
  duplicate, and delete. The brush is held where it was grabbed.

### 2D lighting (ADR 0113)

- **A light buffer** at the sprites' (virtual) resolution, cleared to the
  ambient light, with point and spot lights drawn into it; each lit sprite
  is multiplied by it, so light changes a pixel at a time, in bands if
  asked. Light can reach twice the art's colors (a torch makes a wall
  glow).

## Why it was built this way

- **2D as a first-class path** (ADR 0005), not 3D with flat cameras: pixel
  art needs exact pixels, grid snapping, and sorting by layers and y.
- **Draw small, scale up** is how pixel-art games keep rotation and
  scaling looking like the art, not like smooth vector graphics.
- **Layers as child entities** so sorting, tint, physics layers, and
  hiding are ordinary components, edited like anything else.
- **Lights at the virtual resolution** so lighting looks pixelated like
  the art rather than smooth over it.

## What I'd question

1. **Sorting layers are edited in the project file by hand,** as physics
   layers are: there's no editor UI for adding, ordering, or y-sorting
   them, and `Behind3D` hasn't been tried by hand because of it (open
   items).
2. **No importing levels from other tools.** Tiled (JSON) and LDtk are
   common for 2D levels; the owner asked to come back to importing them
   after M11 (open items).
3. **Tilemap features waiting for a game:** auto-tiling (terrain brushes),
   animated tiles, 90° turns per cell, culling chunks off screen, and a
   trigger layer (water), which needs collision shapes Box2D's chains
   can't be.
4. **2D lighting has no shadows or normal maps,** and no lights limited to
   certain layers; each waits for a game to need it (open items).
5. **The Sprite Sheet Editor is easy to misuse:** dragging to select a
   frame can draw a new one by accident; it needs Select and Draw tools
   (open items, from the owner's try). It's also still part of the
   editor, while tilemaps became a plugin; 2D sprite tooling could follow
   (the "other systems as official plugins" open item).
